# SQLmap 原版使用说明

本目录保存 SQLmap 1.10 原版源码。原版显示英文帮助和运行提示，功能与汉化版一致。

示例中的 `TARGET_URL` 表示你自己的 CTF 靶场或测试地址，`TARGET_DB`、`TARGET_TABLE` 和 `TARGET_COLUMN` 必须替换为工具实际枚举出的名称。

## 1. 启动原版

在 CTFBox 根目录打开 PowerShell：

```powershell
# 基本帮助
.\sqlmap.cmd -h

# 完整参数
.\sqlmap.cmd -hh

# 查看版本
.\sqlmap.cmd --version
```

根目录启动器默认运行原版。源码方式需要 Python 3：

```powershell
py -3 .\Original\sqlmap-1.10\sqlmap.py -h
```

使用 CTFBox 安装版时不需要手动执行这些命令，在 GUI 中选择“SQLmap → 原版”即可。

## 2. 示例一：检测 URL 参数

假设 `TARGET_URL` 中存在参数 `id`：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id --batch
```

- `-u` 指定目标。
- `-p id` 只测试 `id`，避免无关参数拖慢检测。
- `--batch` 使用默认答案，不等待手动确认。

运行时先观察目标是否可连接、参数是否动态，然后查看是否出现类似 `parameter 'id' is vulnerable` 的结论。只有确认存在注入点后，再继续枚举数据。

如果页面响应不稳定，可降低速度并增加超时：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id --delay 1 --timeout 20 --retries 3 --batch
```

## 3. 示例二：检测 POST 参数

假设表单向 `TARGET_URL` 提交 `username` 和 `password`：

```powershell
.\sqlmap.cmd -u "TARGET_URL" --method POST --data "username=test&password=test" -p username --batch
```

如果请求体是 JSON：

```powershell
.\sqlmap.cmd -u "TARGET_URL" --method POST --data '{"id":1,"name":"test"}' --headers "Content-Type: application/json" -p id --batch
```

在 GUI 中对应填写：

1. “目标 URL”：`TARGET_URL`。
2. “请求方法”：`POST`。
3. “请求数据”：实际请求体。
4. “测试参数”：要检测的字段名。

## 4. 示例三：携带登录状态

需要登录的页面通常要带 Cookie：

```powershell
.\sqlmap.cmd -u "TARGET_URL" --cookie "session=TARGET_SESSION" -p id --batch
```

Cookie 失效后会出现重定向到登录页、响应内容相同或参数不动态等现象。遇到这种情况，应先从浏览器或抓包工具获取新的 Cookie，再重新运行。

也可以增加请求头：

```powershell
.\sqlmap.cmd -u "TARGET_URL" --headers "Authorization: Bearer TARGET_TOKEN" -p id --batch
```

## 5. 示例四：读取完整 HTTP 请求

当目标包含复杂请求头、Cookie 或 JSON 数据时，使用请求文件最省事。把抓包内容保存为 `request.txt`：

```http
POST /TARGET_PATH HTTP/1.1
Host: TARGET_HOST
Content-Type: application/x-www-form-urlencoded
Cookie: session=TARGET_SESSION

id=1&name=test
```

然后运行：

```powershell
.\sqlmap.cmd -r .\request.txt -p id --batch
```

请求文件必须保留请求行、`Host` 头、空行和请求体。GUI 中可在“目标 → 原始请求文件”选择该文件。

## 6. 示例五：从数据库枚举到字段数据

以下命令应逐条执行。每一步都使用上一步真实回显中的名称。

### 第一步：枚举数据库

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id --dbs --batch
```

找到目标数据库名后，用它替换 `TARGET_DB`。

### 第二步：枚举数据表

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id -D TARGET_DB --tables --batch
```

找到目标表后，用它替换 `TARGET_TABLE`。

### 第三步：枚举字段

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id -D TARGET_DB -T TARGET_TABLE --columns --batch
```

### 第四步：读取指定字段

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id -D TARGET_DB -T TARGET_TABLE -C TARGET_COLUMN --dump --batch
```

只需要部分行时，可增加范围：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id -D TARGET_DB -T TARGET_TABLE --dump --start 1 --stop 20 --batch
```

在 CTFBox GUI 中执行下一步时，不要点击“清空”。保留目标和请求参数，只修改“枚举”分组。终端会保留前几次运行的回显，方便对照数据库、表和字段名称。

## 7. 调整检测范围

默认配置没有结果时，再逐步增加检测强度：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id --level 3 --risk 2 --batch
```

- `--level` 范围为 1 到 5，值越高，测试位置和载荷越多。
- `--risk` 范围为 1 到 3，值越高，测试行为影响越大。
- `--technique` 可限制检测技术，例如 `BEU` 表示布尔、报错和联合查询。

已知数据库类型时可减少无关测试：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id --dbms MySQL --batch
```

## 8. 会话、日志与输出

SQLmap 会缓存同一目标的检测结果。目标发生变化或需要完整重测时：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id --flush-session --batch
```

查看更详细的请求过程：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id -v 3 -t .\traffic.txt --batch
```

指定输出目录：

```powershell
.\sqlmap.cmd -u "TARGET_URL" -p id --output-dir .\sqlmap-output --batch
```

实际默认输出位置会在启动日志中显示。

## 9. 常见问题

### PowerShell 提示找不到命令

确认当前目录是 CTFBox 根目录，并使用 `.\sqlmap.cmd`，不要省略 `.\`。

### 参数被判断为静态

确认改变参数值时页面内容确实变化；检查 Cookie 是否有效，并尝试使用完整请求文件。

### 目标频繁超时

增加 `--timeout` 和 `--retries`，设置 `--delay`，把 `--threads` 保持在较低值。

### 已修改目标但结果没有变化

使用 `--flush-session` 清除当前目标会话，或使用 `--fresh-queries` 忽略缓存查询结果。

### 需要汉化提示

改用：

```powershell
.\sqlmap.cmd -cn -h
```

`-cn` 必须放在所有 SQLmap 参数之前。
