# SSTImap 原版使用说明

本目录保存 SSTImap 原版源码。原版显示英文帮助和运行提示，功能与汉化版一致。

示例中的 `TARGET_URL` 表示你自己的 CTF 靶场或测试地址。请根据真实请求决定把注入标记放在 URL、请求体、请求头还是 Cookie 中。

## 1. 启动原版

在 CTFBox 根目录运行：

```powershell
# 查看帮助
.\sstimap.cmd -h

# 查看版本
.\sstimap.cmd -V
```

GUI 用户选择“SSTImap → 原版”即可。源码方式需要 Python 3 和项目依赖：

```powershell
py -3 -m pip install -r .\Original\SSTImap-master\requirements.txt
py -3 .\Original\SSTImap-master\sstimap.py -h
```

CTFBox Windows 安装版已经包含运行环境，不需要手动安装依赖。

## 2. 先理解注入位置

SSTImap 有两种指定测试位置的方法。

### 方法一：显式标记

把默认标记 `*` 放到要测试的位置：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*"
```

这是最明确的方式。SSTImap 只在 `*` 所在位置插入检测内容。

需要使用其他标记时：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=INJECT" -M INJECT
```

### 方法二：选择注入区域

请求中没有显式标记时，用 `-P` 指定测试区域：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=test" -P Q
```

区域代码：

- `Q`：URL 查询参数。
- `B`：请求体。
- `H`：请求头。
- `C`：Cookie。

可组合多个区域，例如 `-P QB`。已经放置 `*` 时通常不需要再使用 `-P`。

## 3. 示例一：检测 URL 参数

假设模板渲染了 `name` 参数：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*"
```

运行时重点查看：

1. 请求是否成功到达目标。
2. SSTImap 是否发现反射或模板渲染特征。
3. 回显是否给出模板引擎名称。
4. 哪些检测技术和后续能力可用。

如果 URL 不能加入标记：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=test" -P Q
```

## 4. 示例二：检测 POST 表单

把标记放入请求体：

```powershell
.\sstimap.cmd -u "TARGET_URL" -m POST -d "name=*"
```

多个表单字段可重复使用 `-d`：

```powershell
.\sstimap.cmd -u "TARGET_URL" -m POST -d "name=*" -d "action=preview"
```

如果请求体中没有标记，则指定 `B` 区域：

```powershell
.\sstimap.cmd -u "TARGET_URL" -m POST -d "name=test" -P B
```

GUI 中对应选择 `POST`，在“请求数据”填写 `name=*`。重复参数每行填写一项。

## 5. 示例三：带 Cookie 或请求头

需要登录状态：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*" -C "session=TARGET_SESSION"
```

测试 Cookie 中的值：

```powershell
.\sstimap.cmd -u "TARGET_URL" -C "profile=*"
```

测试自定义请求头：

```powershell
.\sstimap.cmd -u "TARGET_URL" -H "X-Display-Name: *"
```

`-C` 和 `-H` 都可以重复使用。登录状态失效时，先更新 Cookie，再调整检测参数。

## 6. 示例四：限定模板引擎和技术

已经从题目源码、报错或框架特征判断为 Jinja2 时：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*" -e jinja2
```

只使用渲染和报错技术：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*" -e jinja2 -r RE
```

检测技术代码：

- `R`：渲染结果检测。
- `E`：报错检测。
- `B`：布尔盲测。
- `T`：时间盲测。

默认会尝试 `REBT`。目标响应较慢时，可以先用 `RE`，确认需要后再加入盲测。

## 7. 示例五：爬取页面和表单

从入口页向下爬取两层并扫描表单：

```powershell
.\sstimap.cmd -u "TARGET_URL" -c 2 -f
```

排除退出登录等路径：

```powershell
.\sstimap.cmd -u "TARGET_URL" -c 2 -f --crawl-exclude "logout|signout"
```

保存发现的 URL 和表单：

```powershell
.\sstimap.cmd -u "TARGET_URL" -c 2 -f --save-urls .\urls.txt --save-forms .\forms.txt
```

爬取会明显增加请求数量。已知具体入口时，优先直接检测该 URL。

## 8. 交互模式

```powershell
.\sstimap.cmd -i
```

进入后先输入 `help` 查看命令，再使用 `set` 检查或修改目标配置，使用 `run` 或 `check` 开始检测。命令名保持英文。

也可以启动后立即运行检测：

```powershell
.\sstimap.cmd -i --run -u "TARGET_URL?name=*"
```

CTFBox GUI 会把交互提示显示在内置终端，可在终端底部发送输入。

## 9. 记录响应和调整稳定性

把 HTTP 响应写入 SSTImap 日志：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*" --log-response
```

默认日志位于用户目录下的 `.sstimap\sstimap.log`。

目标有频率限制时增加请求间隔：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*" --delay 1
```

时间盲测不稳定时，可分别调整检测和验证延迟：

```powershell
.\sstimap.cmd -u "TARGET_URL?name=*" -r T --blind-delay 5 --verify-blind-delay 30
```

## 10. 常见问题

### 没有发现可测试位置

优先在目标值中加入 `*`。不能修改值时，根据位置使用 `-P Q`、`-P B`、`-P H` 或 `-P C`。

### POST 请求没有按预期发送

确认使用 `-m POST`，并用 `-d` 提供每个请求体参数。JSON 或 XML 请求还需设置正确的 `--data-type` 和请求头。

### 页面每次响应差异很大

增加 `--delay`，先限制为 `-r RE`，必要时再调整布尔匹配与盲测参数。

### HTTPS 证书报错

SSTImap 默认不验证证书。只有目标证书有效且需要严格验证时才启用 `--verify-ssl`。

### 需要汉化提示

```powershell
.\sstimap.cmd -cn -h
```

`-cn` 必须位于所有 SSTImap 参数之前。
