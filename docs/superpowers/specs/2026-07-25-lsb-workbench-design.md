# LSB 隐写工作台设计

## 目标与范围

把现有仅能选择参数的 LSB 页面改造成可离线完成 CTF 图片隐写分析的工作台。第一阶段只实现 LSB 工作台，不扩展同菜单下的“图片隐写”页面；后者后续单独设计 EXIF、PNG 数据块、尾部附加数据、JPEG DCT 和频域分析。

本阶段必须同时保留两条工作流：

1. 自动分析：从常见配置开始，再进行有预算的深度搜索，按证据排序候选结果。
2. 手动提取：用户可完整指定数据源、扫描路径、位流布局、字节打包和变换，并立即复现自动候选。

最终运行只依赖 CTFBox 已打包的前端资源，不调用 Python、zsteg、命令行程序、网络服务或系统中另行安装的工具。

## 架构

新增四个边界清晰的单元：

- `lsbImageSource`：读取文件字节、浏览器解码后的 RGBA 像素，以及受支持 PNG 的原始调色板索引。
- `lsbEngine`：根据结构化参数生成像素顺序和位流，完成字节打包、候选评分、文件识别和雕刻。该模块不依赖 React 或 DOM。
- `lsbArchive`：使用随应用打包的 `fflate` 解压 ZIP/GZIP，执行路径和资源限制，并返回文件树与可预览内容。
- `LsbWorkbench`：负责文件载入、自动/手动模式、进度、候选应用、预览和导出；`MiscWorkbench` 只负责按 `mode` 分派，避免继续膨胀成多种隐写逻辑的集合。

计算密集的自动搜索在 Web Worker 中执行。主线程只进行文件读取、图片解码和界面更新；Worker 使用可转移的 `ArrayBuffer` 接收像素或索引数据，按批次上报进度，并响应取消消息。手动提取复用同一引擎；小输入可直接执行，大输入仍交给 Worker，保证界面可操作。

`TaskState` 增加可选的本地分析状态联合类型，LSB 分支包含运行状态、进度、手动参数、候选摘要、当前结果和错误。`App` 将该状态及更新回调传给工作台，因此切换工具后结果仍保留，且“清空”继续通过现有 `clearTask` 一次清除文件、参数和结果。二进制结果保留为 `Uint8Array`/`ArrayBuffer`，不序列化进 `ToolParameters`，也不进入命令构造器。

## 输入数据源

每次载入文件都保留原始字节，并生成以下可用数据源：

1. 渲染像素：通过 `createImageBitmap` 或 `Image` 加 Canvas 得到标准 RGBA，每个通道为 0 到 255。PNG、BMP、JPEG、GIF 等浏览器可解码格式均可进入此路径；有损格式只表示解码后的像素。
2. PNG 调色板索引：解析 PNG 签名和 IHDR/IDAT/IEND，验证基础结构，使用 `fflate` 解压 IDAT，并反滤波得到索引。首版支持非隔行、色型 3、位深 1/2/4/8；不满足条件时给出明确原因并继续使用渲染像素。

图片解码失败、PNG 结构损坏或尺寸超限时显示可定位的错误，不留下上一个文件的候选结果。切换文件会取消正在运行的旧任务，以任务序号丢弃迟到结果。

## 手动参数模型

手动参数是可序列化的结构化对象，并由同一对象驱动控件、参数摘要和引擎调用：

```ts
interface LsbExtractionParameters {
  sourceKind: "rgba" | "palette-index";
  sources: Array<{ channel: "R" | "G" | "B" | "A" | "I"; bit: 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 }>;
  scan: {
    major: "row" | "column";
    x: "left-to-right" | "right-to-left";
    y: "top-to-bottom" | "bottom-to-top";
    serpentine: boolean;
    reversePixels: boolean;
  };
  layout: "pixel-interleaved" | "channel-block";
  packing: "msb-first" | "lsb-first";
  bitOffset: 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7;
  invertBits: boolean;
  reverseBytes: boolean;
  byteOffset: number;
  byteLimit?: number;
  terminator?: string;
}
```

“数据源顺序”使用可排序的令牌列表表达，而不是单一通道多选框。用户可添加任意 `R/G/B/A × 0..7` 令牌、重复令牌、拖动排序或删除，并可应用常用预设。这样可以直接表达 `R0,G0,B0`、`A0,B0,G0` 和 `R4,R2,R1,G4,G2,G1`，控件显示的顺序就是实际读取顺序。

扫描方向由主轴、X 方向、Y 方向组合成八种基础方向；蛇形扫描使每条次轴交替反向，反转像素在生成扫描序列后整体倒序。位偏移发生在打包前，字节偏移发生在打包后。位反转先于打包，字节内位序由 `packing` 决定，字节反转最后作用于完整输出。界面始终显示这一固定处理顺序。

## 自动分析

自动分析提供“快速”和“深度”两档，默认快速；两档使用同一候选模型和评分规则，仅搜索预算不同。搜索按阶段执行，避免对每个组合完整提取整张图片：

1. 预设阶段：覆盖单通道、RGB/BGR/RGBA/ARGB 等常见顺序、同位平面、八种基础扫描方向、蛇形开关、两种打包方式和两种布局。
2. 混合位阶段：从有序通道子集和每通道 1 到 4 个有序位组成数据源。位组合至少覆盖 0 到 7 的升序、降序和所有组合的升降序，因此必须包含 `R4,R2,R1,G4,G2,G1`。先只提取短前缀并保留高分配置，再对保留项展开位偏移、位反转、字节反转和布局变化。
3. 完整验证阶段：只对前两阶段排名靠前的配置提取完整数据，运行签名识别、文件长度计算、雕刻、解包和最终评分。

快速档限制混合位搜索到高信号通道、常见位序和固定候选数；深度档覆盖上述完整组合。搜索预算由“候选配置数量”和“前缀读取字节数”控制，不使用不可预测的无限循环。界面显示已测试数量、当前阶段、耗时和取消按钮。达到预算时返回已有候选并标记“搜索预算已用完”，不把它显示成失败。

自动候选保存完整的 `LsbExtractionParameters`。点击“应用参数”会切换到手动模式、填充所有控件并重新提取；自动结果与手动结果必须逐字节一致。

## 评分与候选去重

候选分数由可解释证据相加，不使用单一“可打印率”判断：

- 匹配全局 Flag 前缀设置及通用 `flag{...}` 形态。
- 文件签名位于开头，或可在结果中雕刻出结构完整的文件。
- UTF-8/ASCII 可打印率、连续文本长度和合理换行。
- ZIP/GZIP 解包成功、容器长度自洽、内部文件含文本或 Flag。
- 对高熵、全零、周期性单字节和明显噪声施加惩罚。

每项证据在候选详情中单独列出。候选按“内容哈希 + 有效长度”去重；相同内容只保留最高分参数，并列出其他可复现配置。评分相同时优先参数更简单、扫描更常见的配置，保证排序稳定且测试可重复。

## 文件识别、雕刻与解包

内置签名识别至少覆盖 PNG、JPEG、GIF、ZIP、GZIP、PDF、7z、RAR、BMP、WAV 和 ELF。对有明确结束结构的格式计算真实边界：PNG 到 IEND、JPEG 到 EOI、GIF 到 trailer、ZIP 到对应 EOCD；对其他格式使用可验证长度字段或保留剩余字节并标注依据。

识别到签名不在偏移 0 时，结果中显示偏移并允许雕刻导出。ZIP 必须按 EOCD 结束位置截取，不能把后续 LSB 噪声交给解压器。ZIP/GZIP 在 CTFBox 内解包，文件名按 UTF-8 标记优先并保留无法解码时的原始名称提示；文本文件直接预览并再次扫描 Flag，二进制文件可查看十六进制和单独导出。

归档处理拒绝绝对路径、盘符路径和 `..` 路径穿越。单次最多展示 512 个条目、总解压 256 MiB、单文件 128 MiB、压缩比 500:1；超过限制时保留容器识别和原始导出能力，并明确列出被限制的项目。

## 界面与交互

LSB 页面沿用现有三块布局，但把占位区域替换为实际工作台：

- 输入区：拖放/选择图片、原图预览、尺寸和数据源状态；可切换原图、R/G/B/A 通道和 0 到 7 位平面预览。
- 参数区：顶部使用“自动分析 / 手动提取”分段控件。自动模式选择快速或深度；手动模式按数据源、扫描、布局、打包、偏移和输出限制分组。
- 结果区：自动模式显示候选表，手动模式显示单个结果。详情用“文本、十六进制、文件、位平面/通道”标签页，Flag 置顶但不隐藏其来源。

候选表至少显示排名、分数、内容类型、预览、数据源顺序和扫描摘要。选择候选后可“应用参数”“导出原始字节”“导出雕刻文件”；归档结果可展开文件树并逐项导出。导出使用浏览器 Blob 和 Tauri/浏览器可用的保存流程，不依赖外部程序。

运行期间禁用会改变当前任务语义的参数，但允许取消、切换预览和查看已完成候选。取消后状态为“已取消”，保留已经完成的候选；再次运行会替换当前运行的候选，而切换标签页或工具不清空结果。只有“清空”或载入新文件会清除旧结果。

所有图标按钮使用现有 Lucide 图标并提供 `title`/可访问名称。选中态在明暗主题中都必须具有可辨识的背景、边框和文字对比度；窄窗口下参数区和结果区纵向排列，令牌列表及按钮文字不得溢出。

## 错误与资源控制

- 文件为空、格式不可解码、无可用通道、数据源列表为空、偏移非法时，在参数附近显示具体错误并阻止运行。
- 默认输入上限为 512 MiB，解码像素上限为 10000 × 10000；超过限制时在分配大数组前终止。
- 单候选完整提取默认最多保留 128 MiB；手动模式允许设置更小的字节上限。
- Worker 异常和解压异常转为结构化错误，不能使整个 React 页面崩溃。
- 所有对象 URL 在替换文件、清空和组件卸载时释放；Worker 在取消、清空和卸载时终止。

## 测试策略

引擎测试使用程序化生成的小图片/像素数组，不依赖浏览器截图：

- 覆盖 RGBA 各位平面、有序混合位、像素交错和通道分块。
- 覆盖八种方向、蛇形、反转像素、两种打包、位/字节偏移、位反转和字节反转。
- 覆盖非字节对齐尾部、结束标记、输出限制和非法参数。
- 覆盖候选评分稳定性、内容去重、常见签名边界和嵌入偏移雕刻。
- 覆盖 ZIP/GZIP 解包、UTF-8 文件名、Flag 递归发现、路径穿越和解压上限。
- 覆盖非隔行调色板 PNG 的 1/2/4/8 位索引反滤波，以及损坏 PNG 的降级路径。

组件测试覆盖文件替换、自动/手动切换、运行/取消、候选应用、参数摘要、标签页、导出可用状态、错误状态和清空语义。任务状态测试覆盖切换 LSB 与其他工具后结果隔离且仍可恢复。

UI 验收使用明暗主题和桌面/窄窗口截图，检查选中态、滚动、长文件名、长参数序列、候选表和归档树。提交前运行：

```powershell
pnpm --dir gui test:unit
pnpm --dir gui typecheck
pnpm --dir gui build:renderer
```

## 后续边界

完成并验收本设计后，再为“图片隐写”模块单独编写设计。该模块可以复用文件载入、结构化结果、十六进制/文本预览、导出、Worker 生命周期和资源限制，但不会把 EXIF、PNG 数据块、尾部数据、JPEG DCT 或 FFT 搜索塞入 LSB 引擎。
